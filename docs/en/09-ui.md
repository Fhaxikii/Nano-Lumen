## Architecture: one process, UI and kernel together

All UI code lives in `app.py` (~17k lines, most of it the `WebUI` class from
:948 on). NiceGUI (FastAPI + Vue/Quasar) renders; pywebview / WebView2 wraps it
into a native window.

Three structural facts to confirm before touching any UI code:

1. **The UI never calls models or tools directly**; everything goes through the
   orchestrator. The UI consumes the `agent.handle_query(...)` event stream
   (see [09b](09b-chat-events.md)).
2. **UI elements hang on NiceGUI's auto-index client (a process-level
   singleton)** — refreshing the page does not rebuild the element tree;
   **background threads must explicitly enter the client context to write UI**,
   or the change silently disappears. The RAG init thread once hit the event
   bus before `ui.run()` (around app.py:1115).
3. **What the user sees and what occupies the context are two questions**:
   system notes with `visible_to_user=False` are visible to the model but not
   the user; exports must filter them (see 07a).

## Startup order (⚠️ most traps in this file live here)

```
process start → tray (pystray, ~:261) → synchronous init (~:16687, must run
synchronously before ui.run(), not on a ui.timer) → WebUI() → ui.run() 
→ WebView2 native window → client connect (_on_browser_connect)
```

Known trap: if the RAG init thread starts during `WebUI()` construction, it runs
before `ui.run()` — any "writes to the UI during startup" code must check which
thread it runs on and when. Details: [09a](09a-startup-window.md).

## Known limits (no promises)

- NiceGUI cannot provide an embedded browser (web links always open in the
  system default browser).
- The koala is a sprite animation, not true skeletal rigging (see README known
  limits).
- I18N incomplete: the language setting only affects the model's generated
  language, not the UI text.

## How to verify you got it right

1. `bash run_tests.sh` (UI-related: `t_u3_chat_surface.py`,
   `t_u7_card_layout.py`, `t_u7_reply_lifecycle.py`, `t_u8_tool_detail.py`,
   `t_ui_edge_l25_l27.py`, etc.).
2. Walk the changed area under both themes.
3. For async UI writes, verify "still there after page refresh" (client
   singleton semantics).
4. For startup-order changes: one cold start plus one restart with history.
