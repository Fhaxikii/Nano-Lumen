## Stack

The UI is built with NiceGUI and runs in a WebView2 window hosted by
pywebview. It is a local web application, so HTML, CSS, and a little
JavaScript are available — within the capability boundaries of WebView2.

All UI code is in `app.py`. The file is large; locate things by symbol name
rather than reading it end to end.

The three colored dots in the top-left open the settings panel — they are
not window controls. Minimize/maximize/close are in the top-right.

Four drawers slide out from the right; only one is visible at a time.

## The style system

Every color and font size is defined via CSS variables; no values are
hardcoded on elements. The variables come in families:

| Prefix | Purpose |
|---|---|
| `--nano-bg` `--nano-panel` `--nano-chrome` `--nano-input` | Background layers |
| `--nano-border` `--nano-line` | Separators |
| `--nano-fg` `--nano-fg-soft` `--nano-fg-mute` `--nano-dim` `--nano-faint` | Five text tiers |
| `--nano-ok` `--nano-danger` `--nano-warn` `--nano-info` `--nano-amber` | Semantic colors |
| `--nano-fs-*` | Font-size scale |
| `--nano-cm-*` | Code highlight palette |
| `--nano-brand-*` | Brand colors, identical across both themes |

Variables with an `-rgb` suffix hold bare numbers (no `rgb()` wrapper) for
composing alpha values.

Font-size variables are named by tier, not by pixel value. A variable named
after pixels starts lying the moment the value is adjusted.

## Themes

Two themes, switched by adding a class to `body`; all colors ride on CSS
variables:

```
body.nano-theme-light      light
body.nano-theme-terminal   dark
```

To add a theme, add a `body.nano-theme-xxx { --var: value; }` block — no
element code changes.

Theme-independent variables must be defined in the shared block, not inside
one theme, or they will go missing when switching to the other.

## Adding a settings item

The settings panel has five categories, defined in `_SETTINGS_TABS` in
`app.py`: General, Personal info, OS Permissions, MCP Connections, Advanced.

Each category maps to a `_build_settings_*` method. To add a setting:

1. Add the control in the matching `_build_settings_*` method.
2. Persist to a config file under `data/`; see
   [03-configuration.md](03-configuration.md).
3. On save, call the matching refresh function immediately — no restart.
4. If the setting affects a permanently-mounted control, refresh it
   explicitly. Panels rebuilt on every open pick up new values by
   themselves; permanently-mounted controls do not.

## Adding a drawer

Drawer visibility is controlled by `_show_right_panel` in `app.py`. A new
drawer needs an entry tab in the top bar and a matching branch in that
method.

## UI copy

UI copy follows the user's language. Text sent to the model is in English.
The criterion is "who reads this text". If the two renderings of one feature
are hardcoded in two separate places, changing one leaves the other lying —
copy aimed at both audiences must be derived from a single source.

## Patterns to watch for

**Multiple writers to the same UI element**
If several places update one element and only some follow a rule, the rule
is not actually in effect. Converge all writers into one function.

**What may never enter the Kernel**
The runtime kernel (`core/runtime/`) carries **authoritative runtime state**
only. Pure display state is forbidden inside: the current text of a
streaming reply (`ViewSession.current_text`), spinner frames, block
expand/collapse, scroll position, temporary Markdown references.

The test: "what breaks if this state is lost?" If losing it only affects
what is seen this once, it is display state, naturally rebuildable from
authoritative state. If losing it makes the system wrong about facts, it is
authoritative state.

Pushing display state into the Kernel has no immediate cost, so it creeps in
bit by bit until the Kernel becomes the UI's state dumpster — and every new
UI effect then requires touching the kernel.

**Where blocking calls go**
Do not put time-consuming work before UI elements are created. The clock
started earlier, but the UI only appears seconds later — it looks frozen,
not busy.

## How to verify you got it right

1. Check the change under both themes; colors correct, no hardcoded values
   left behind.
2. Resize the window; the layout does not overflow.
3. Change a setting without restarting: it takes effect immediately. After a
   restart: it survives.
4. If the change touches a permanently-mounted control, perform an action
   that should change it and confirm it does.
5. Run `bash run_tests.sh`.
