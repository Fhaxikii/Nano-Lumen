# 09b · 聊天区与事件流

**这篇讲什么**：界面的心脏——`agent.handle_query` 事件流如何被消费成聊天区：统一文字流、工具卡、response epoch 与续接 seam、滚动策略、对话重放。  
**读完你能做什么**：新增一种事件渲染、调整流式行为或工具卡布局，而不破坏 epoch/seam 这套防竞态结构。  
**前置**：[09 总览](09-ui.md)。

## 事件流的消费骨架

聊天不自己产生内容，它消费编排层的事件流（:3615 一带）：

```python
_stream = self.agent.handle_query(query, image_parts=..., temp_file_hint=...)
async for step in _stream:
    # 按 step["event"] 分发渲染
```

**统一文字流**（这节的灵魂）：`thought_block_start / thought_block_done /
thought_summary` 不再创建独立可折叠块——**思考文字与最终答案同字体同样式
直接流入同一个 markdown 元素**，"思考流和回答浑然一体"。`thought_delta`
逐段追加。给"思考过程"单独建块的设计已被推翻过一次，别走回头路。

## response epoch 与续接 seam

一次"回答纪元"（response epoch）拥有一套渲染状态 `_rs`（当前文字、spinner、
元数据行等）。**关键机制**：

- **一个 epoch 只有一个状态计时器**：载体（carrier）完成可能**续接同一
  epoch**——续接前必须取消旧计时器再起新的（:3610 一带的
  `_status_timer_task` 取消逻辑），否则两个任务竞争渲染同一行元数据。
- **续接 seam**：续接发生时，准备逻辑清空 `content_md`、复位
  `current_text`、重新显示 spinner——失败时**退化成覆盖同一元素**而不是
  另起一个。日志里的 `[Seam]` 前缀就是它。
- `waiting_for_carrier` 标志位管理"等载体"与"在生成"两种形态。

改流式行为的自检问题：**同一段内容在续接场景下会不会出现两个渲染载体？**
出现就是 seam 破了。

## 工具卡与过程可视化

- 工具调用以**卡片**形式在聊天区展开（布局细节归 `t_u7_card_layout` /
  `t_u8_tool_detail` 把守）。
- **路由/内部步骤信息不进聊天区**——log 事件只写监控面板（:4405 注释）。
  判断标准："用户要看见过程"的进聊天区，"调试信息"进监控。
- 记忆类动作（Nano 记住了什么）走**统一气泡 + 记忆抽屉待确认卡片**
  （，不在聊天区刷细节。

## 滚动策略

`_pin_chat_bottom` / `_scroll_chat_to_bottom`（:5219/:5232）：**保持贴底**，
用户向上翻阅历史时不强制拉回（v1.95 的修复）。流式内容追加的滚动更新
必须尊重"用户正在向上看"这个状态。

## 对话重放

`_replay_durable_conversation`（：重启/切换会话后把落盘账本重画
成气泡。两条纪律：

1. **它只负责画**——渲染持久对话的投影，不参与衰减/投影重建（那是
   07a `rebuild_projection` 的领地，重放读它的结果）。
2. **按 role 分组画气泡，过滤 `visible_to_user=False`**——用户没见过的
   系统注记重放后也不能出现（导出走同一条纪律，见 07a）。

## 改动手把手

**场景 A：新增一种事件的渲染**
在事件分发处加分支。先回答：它进聊天区还是监控面板（判断标准见上）？
进聊天区的，考虑统一文字流（别为新事件单开容器）；改动后跑
`t_u3_chat_surface.py`。

**场景 B：调整流式/续接行为**
动 `_rs` 相关逻辑前，先复述一遍 epoch 所有权：谁拥有计时器、续接时谁
取消谁。加状态位时明确它在 seam 两边各是什么值。

**场景 C：改滚动行为**
以"贴底但不打扰"为不变量；任何"强制拉底"都要有用户主动发消息作为
触发条件。

**场景 D：改重放**
只动渲染，不动投影；新旧会话各验一遍，带图片的历史要验证图片引用
仍能取回（07a 的图库路径）。

## 怎么验证你改对了

1. `bash run_tests.sh`（本篇对应 `t_u3_chat_surface.py`、
   `t_u7_reply_lifecycle.py`、`t_u8_tool_detail.py`、`t_exit_tool_card.py`）。
2. 真机：一次带工具调用的长回答——思考与答案应连续流入同一气泡；
   工具卡展开正常；向上翻阅时不被拉回。
3. 续接场景（触发一次载体完成后续接）：元数据行不重复、不竞态。
4. 重启后重放：气泡完整、无系统注记泄漏、图片可看。
