# 09 · 界面

**这篇讲什么**：界面的技术栈、结构、样式体系，以及新增一个面板的做法。  
**读完你能做什么**：修改界面元素或新增设置项与面板。

## 技术栈

界面用 NiceGUI 构建，运行在由 pywebview 承载的 WebView2 窗口中。
它是一个本地 Web 应用，因此可以使用 HTML、CSS 与少量 JavaScript，
但受 WebView2 的能力边界约束。

全部界面代码在 `app.py`。这个文件很大，改动前建议先用符号名定位而不是通读。

## 结构

```
┌────────────────────────────────────────────────────────┐
│ ●●●  nano@用户      [模型下拉] ★   [知识库][监控][任务][记忆] │
├──────────────┬─────────────────────────────────────────┤
│              │                                          │
│  工具面板     │              聊天区                      │
│  ~/tools     │                                          │
│              │                                          │
│              ├─────────────────────────────────────────┤
│  [主题切换]   │  [输入框]                                 │
│              │  [自动模式]                      [主动程度] │
└──────────────┴─────────────────────────────────────────┘
```

左上角三个彩色圆点是设置面板的入口，不是窗口控制按钮。
窗口的最小化、最大化、关闭在右上角。

四个抽屉从右侧滑出，同一时刻只显示一个。

## 样式体系

所有颜色、字号都通过 CSS 变量定义，不在元素上写死数值。
变量分为几族：

| 前缀 | 用途 |
|---|---|
| `--nano-bg` `--nano-panel` `--nano-chrome` `--nano-input` | 底色层次 |
| `--nano-border` `--nano-line` | 分隔线 |
| `--nano-fg` `--nano-fg-soft` `--nano-fg-mute` `--nano-dim` `--nano-faint` | 文字五档 |
| `--nano-ok` `--nano-danger` `--nano-warn` `--nano-info` `--nano-amber` | 语义色 |
| `--nano-fs-*` | 字号阶梯 |
| `--nano-cm-*` | 代码高亮配色 |
| `--nano-brand-*` | 品牌色，两套主题下同值 |

带 `-rgb` 后缀的变量存放不带 `rgb()` 包装的数值，用于需要拼接透明度的场合。

字号变量按档位命名而不是按像素值命名。按像素值命名的变量一旦被调整，
名字就开始说谎。

## 主题

两套主题通过给 `body` 添加类名切换，配色全部由 CSS 变量承载：

```
body.nano-theme-light      浅色
body.nano-theme-terminal   深色
```

新增主题的方式是增加一个 `body.nano-theme-xxx { --变量: 值; }` 块，
不需要改动任何元素代码。

与主题无关的变量必须定义在公共块中，不能只定义在某一套主题里，
否则切到另一套主题时该变量会缺失。

## 新增一个设置项

设置面板有五个分类，定义在 `app.py` 的 `_SETTINGS_TABS`：
通用、个人信息、OS 权限、MCP 连接、进阶配置。

每个分类对应一个 `_build_settings_*` 方法。新增设置项的步骤：

1. 在对应的 `_build_settings_*` 方法中添加控件。
2. 读写落到 `data/` 下的配置文件，参见 [03-configuration.md](03-configuration.md)。
3. 保存后立即调用对应的刷新函数，不要求用户重启。
4. 如果这个设置影响某个常驻控件，需要显式刷新它。
   每次打开都重建的面板会自动反映新值，常驻控件不会。

## 新增一个抽屉

抽屉的显示由 `app.py` 的 `_show_right_panel` 控制。
新增抽屉需要在顶栏添加入口标签，并在该方法中添加对应分支。

## 界面文案

界面文案跟随用户语言。送给模型的文本使用英文。
判断依据是"谁读这段文字"。同一个功能的两种表述如果分别硬编码在两处，
改动其中一处后另一处就会开始说错，因此涉及两个受众的文案
应当从同一处派生。

## 需要注意的模式

**同一块界面的多个写入口**
如果一个界面元素有多个地方会更新它，而只有其中一部分遵守某条规则，
那条规则实际上不生效。所有写入口应收敛到一个函数。

**哪些状态不许进 Kernel**
运行期内核（`core/runtime/`）只承载**权威运行状态**。纯展示状态不许往里放，
具体指：流式回复的当前文本（`ViewSession.current_text`）、spinner 的帧、
区块的展开与折叠、滚动位置、临时的 Markdown 引用。

判据是「这个状态丢了会怎样」：丢了只影响这一次看到的画面，就是展示状态，
它天然可以从权威状态重建；丢了会让系统对事实的判断出错，才是权威状态。

把展示状态推进 Kernel 没有立刻的坏处，所以它会一点一点发生，
最后 Kernel 变成 UI 状态垃圾桶——那时每加一个界面效果都要动内核。

**阻塞调用的位置**
耗时操作不要放在界面元素创建之前。计时从更早的时刻开始，
界面却在若干秒后才出现，表现上是卡死而不是等待。

## 怎么验证你改对了

1. 在两套主题下分别查看改动，确认颜色都正确，没有硬编码的色值残留。
2. 缩放窗口，确认布局不溢出。
3. 修改设置后不重启，确认立即生效；重启后确认设置保留。
4. 如果改动涉及某个常驻控件，触发一次会改变它的操作，确认它跟着变了。
5. 运行 `bash run_tests.sh`。
