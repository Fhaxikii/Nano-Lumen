## 架构：单进程，UI 与内核同生共死

全部界面代码在 `app.py`（约 1.7 万行，其中 `WebUI` 类自 :948 起占绝大多数）。
NiceGUI（FastAPI + Vue/Quasar）渲染，pywebview / WebView2 包成原生窗口。

三条结构性事实，改任何 UI 代码前先确认：

1. **UI 不直接调用模型或工具**，全部经过编排层；界面消费的是
   `agent.handle_query(...)` 的事件流（见 [09b](09b-chat-events.md)）。
2. **UI 元素挂在 NiceGUI 的 auto-index client 上（进程级单例）**——
   刷新页面不重建元素树；**后台线程写 UI 必须显式进入 client 上下文**，
   否则改动静默丢失。RAG 初始化线程就曾因早于 `ui.run()` 启动而踩过
   事件总线（app.py 一带）。
3. **给用户的显示与占上下文是两个问题**：`visible_to_user=False` 的系统注记
   模型看得见、用户看不见；导出时它们必须被过滤（见 07a）。

## 启动时序（⚠️ 全文件最容易踩的坑都在这里）

```
进程启动 → 托盘（pystray，:261 一带）→ 同步初始化（:16687 一带，必须在
ui.run() 之前同步跑，不能挂 ui.timer）→ WebUI() 构造 → ui.run()（
→ WebView2 原生窗口 → 客户端连接（_on_browser_connect）
```

已知坑：RAG 初始化线程若在 WebUI 构造时启动，会早于 `ui.run()`——
任何"启动期就往 UI 写"的代码都要检查自己跑在哪个线程、什么时点。
详见 [09a](09a-startup-window.md)。

## 已知边界（不承诺）

- NiceGUI 无法实现内置浏览器（网页链接一律交系统默认浏览器）。
- 考拉是精灵图动画，非真骨骼（见 README 已知边界）。
- I18N 未完成：语言设置只影响模型生成语言，不影响 UI 文案。

## 怎么验证你改对了

1. `bash run_tests.sh`（界面相关：`t_u3_chat_surface.py`、`t_u7_card_layout.py`、
   `t_u7_reply_lifecycle.py`、`t_u8_tool_detail.py`、`t_ui_edge_l25_l27.py` 等）。
2. 明暗两套主题下分别过一遍改动区域。
3. 改动涉及异步写 UI 时，验证"刷新页面后仍在"（client 单例语义）。
4. 启动顺序类改动：冷启动一次 + 带历史重启动一次。
