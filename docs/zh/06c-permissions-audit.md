## 意图一致性分类器（`cmd_classifier.py`）

Auto 模式下对 `run_command` 的判定器。四类判定：安全（放行）/ 低危（放行）/
**危险（弹窗）** / 判不了（弹窗，保守）。

**「危险」必须同时满足三个条件（设计铁律）**：

1. 是 `run_command`（进得了判定）；
2. ∧ 属于高危指令类（删 / 装 / 改 / 杀 / 外传…）；
3. ∧ **跟用户要做的事对不上**。

🔴 **③ 是整件事的核心，没有它一文不值。** 只有 ①② 的话，它退化成
「删除 = 危险」——那是正则表就能做的事，而且会拦掉用户明确要求的删除：

```
用户「帮我清理临时文件」  + del /q /f %temp%\*  → 对得上 → 不拦
用户「看看这个txt写了啥」 + del /q /f %temp%\*  → 对不上 → 必须拦
```

⇒ **危险不是命令的属性，是「动作偏离了意图」的属性。** 同一条命令，两种判定。

**判定器看什么——reasoning-blind by design**（照抄官方分类器）：

- 看：用户消息（意图）+ 这一条工具调用（动作）
- 不看：模型自己的推理（它正是被核对的对象，不能自辩）
- 不看：工具输出（**注入的载体**，让它进判定器等于把闸交给攻击者）

⭐ ③ 同时是**注入防御**：注入能让模型发出危险命令，但**改不掉用户真正说过
的话**——要成功必须同时骗过用户和判定器。

工程细节：会话级缓存键**必须带意图指纹**（`_cache_key`，:98）——同一条命令
换一个意图就是另一个问题；换会话时 `reset_cache`（:106）。脚本类命令先做
AST 预扫描（`prescan_script`，:166）：纯标准库的安全脚本不用问意图直接放行。

## 审计流水（`audit.py`）

- **append-only，一行一条 JSON**：`data/os_audit/os_actions.log`。
- **只读动作也照样写**——"每个 OS 动作都留痕"不分档位。
- 与 working memory 刻意区分：working memory 是给模型 recall 的语义记忆
  （可筛选、可格式化）；审计日志是**不可篡改的全量流水**，用于事后追溯。
- 每条记录带风险与升级原因（来自 [06a](06a-instructions-risk.md) 的
  `reasons`），回答的不只是"做了什么"，还有"为什么允许做"。

## 敏感路径黑名单（`pathpolicy.py`）

**黑名单而不是白名单**——与子智能体的工具集（白名单）方向相反，各自有理：

- 子代理工具集用白名单：排除法的欠账随时间增长。
- 路径策略用黑名单：合法路径空间无限（用户哪儿的文件都可能要读），无法枚举；
  但危险位置有限且可枚举（凭据、私钥、浏览器密码、
  `C:\Windows\System32\config\SAM` 之类）。

读与写策略不同：读走 KB 侧宽松策略但仍必须过黑名单。

## canary 自检（`canary.py`）

空闲时验证视觉定位链路是否正常，两条纪律：

1. **目标必须稳定常驻**：用 Windows 任务栏标准按钮（搜索/任务视图/通知），
   不用"记事本是否开着"这种临时窗口——否则"目标不存在"会污染"定位失败"
   的统计。直接定位任务栏窗口（Shell_TrayWnd），不走"猜用户想操作哪个窗口"。
2. **只在空闲时跑**：canary 要做 UIA 定位，与真实任务并发会重新引入"自检
   抢占前台焦点"这个刚修过的问题。`should_run()` 同时检查间隔与空闲。

连续低分达到 `escalate_after_consecutive_low`（配置默认 3）会升级上报；
判定逻辑在 `run_once()`，调用方负责真正的处理。

## 授权作用域（`safety.py`）

- 会话级"始终允许"只对 risk=2 生效；**risk=3 永远单独确认**。
- 步数 / replan 计数器也在这里。
- 曾有的第三种"软急停"已删除（无复位路径的进程级标志），故事见
  [06b](06b-execution-pipeline.md)。**安全机制没有复位路径，本身就是风险。**

## 改动手把手

**场景 A：调整分类器的判定范围**
高危指令类清单与脚本 AST 预扫描都在 `cmd_classifier.py`。改动的自检问题：
新的判定是否仍然**以意图一致性为核心**？只按命令特征判定 = 退化成正则表。
改完跑 `t_cmd_classifier.py`，重点看"用户明确要求的删除"这类用例没有被误拦。

**场景 B：扩展审计或路径策略**
审计：保持 append-only 与"只读也记"两条性质（`t_audit_semantics.py`）。
路径：只加黑名单条目；想收窄成白名单前先读 `pathpolicy.py` 头部关于两种
方向的理由。

**场景 C：换 canary 目标**
必须满足"稳定常驻"纪律；`t_shot_prune.py` 与配置里的 `canary.interval_seconds`
/ `success_threshold` / `escalate_after_consecutive_low` 是调参入口。

## 怎么验证你改对了

1. `bash run_tests.sh`（本篇对应 `t_cmd_classifier.py`、`t_audit_semantics.py`、
   `t_os_capability_gate.py`）。
2. 真机：Auto 模式下分别说"帮我清理临时文件"与"看看这个 txt"后让它删同
   一个目录——前者应放行、后者应弹窗。
3. 任意一次 OS 操作后检查 `data/os_audit/os_actions.log` 末行：JSON 完整、
   含风险与原因。
4. 关掉某个权限开关后重复操作，确认拒绝理由指向该开关。
