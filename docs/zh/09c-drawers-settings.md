# 09c · 抽屉、监控与设置

**这篇讲什么**：聊天区之外的全部界面——右侧抽屉（单 drawer 多面板）、健康驱动的监控卡、上下文圆环、六张设置页与数据导出。  
**读完你能做什么**：新增一个面板/设置项、调整监控卡显示策略，而不破坏"多个 drawer 抢布局槽位"这条已经修过的结构。

## 右侧抽屉：一个 drawer，多个面板

⭐ **结构是刻意改过的**（:1042 注释）：曾经是 3 个独立的 `ui.right_drawer`
抢同一个布局槽位——NiceGUI/Quasar 的 q-layout 假设一侧只有一个 drawer，
多个右抽屉在 hide()/toggle() 切换时布局的 `padding-right` 计算出现顺序依赖，
"先开监控再切别的"留白跟丢。**修法：只挂一个 `right_drawer`，里面放多个
内容面板切换可见性**——从根上消除"多个 drawer 抢布局槽位"这个前提。

面板清单（`WebUI.__init__`，:1050 一带）：

| 面板 | 变量 | 内容 |
|---|---|---|
| 监控 | `monitor_panel` | 健康卡 + 上下文占用 |
| 知识库 | `kb_panel` | KB 文件与状态 |
| 记忆 | `memory_panel` | 待确认/已确认记忆卡片 |
| 后台任务 | `tasks_panel` | 运行中任务 + 完成记录（Clear 只隐藏不删） |
| Subagent | `agent_panel` | 分身监控（无并列按钮，盯住哪个由 `_agent_watch` 决定） |

**新增面板的正确姿势**：在现有 `right_drawer` 里加一个 panel + 导航行，
**绝不再挂第二个 `ui.right_drawer`**。

聊天区里还有一个 `_task_pill`（"x running task(s)"）——它是抽屉的
聊天区内入口形态，与抽屉徽章（`_tasks_badge_label`）同源。

## 监控卡：可用性优先，说真话

- **聊天区（给用户看）：只有【不可用】才出卡；degraded 只进监控面板**
  （:7899 注释）——落点是让监控卡说真话，不是往聊天区塞卡片。
- 配色档位（：**前三档是可用性，后三档是活动状态**——故障态覆盖
  活动态显示（`_refresh_health_card`，:8105 按 HealthRegistry 重绘）。
  RAG 这类"降级但能用"的能力只在监控面板里降档显示。
- 监控卡刷新是**被动触发**（健康事件/操作后），不是定时轮询刷屏。

## 上下文圆环：同一个数，两个出口

- **监控卡的「上下文」与输入框右下角的圆环是同一个数**——都读
  `budget.snapshot`（。两个出口显示不一致 = 消费方各自取数的 bug。
- `_refresh_context_card`（/ `_refresh_context_ring`（；
  画环纪律：**量不到 / 失准 → 空心灰环，不是 0%**（与监控卡同一条纪律：
  "不知道"不许被画成"很好"）。

## 六张设置页（7104-10700）

| 页 | 构建 | 内容 |
|---|---|---|
| OS 权限 | `_build_settings_permissions`（ | 六个权限开关（生效机制见 06a 的 perms） |
| 个人信息 | `_build_settings_profile`（ | persona 相关 |
| 花费上限 | `_build_settings_cost_cap`（ | 软/硬上限，硬上限停发请求 |
| MCP 连接 | `_build_settings_mcp`（ | server 列表、状态、授权卡入口 |
| 进阶配置 | `_build_settings_advanced`（ | 视觉模型、主动程度档位（预留，无实际影响）等 |
| 通用 | `_build_settings_general`（ | 语言 / 用量限额 / 环境配置 / **导出数据** |

通用约定：配置落盘后**立刻刷新受影响的显示，不需要重启**（:10182 的
"落盘 + 立刻刷新监控卡"）。

## 数据导出

入口在「设置 → 通用 → 导出数据」（。两条已在 UI 文案里说清的语义：

- **导出的是全部对话记录，包括已经重置掉的**（"重置"是放弃不是删除，
  与 07a 的 export 语义一致）。
- 导出走 `core/runtime/export.py`：Markdown + 原始 JSON + 图片副本，
  过滤 `visible_to_user=False`。

## 改动手把手

**场景 A：新增一个面板/设置项**
面板：现有 `right_drawer` 内加 panel + 导航行 + 可见性切换；不挂第二个
drawer。设置项：放进对应设置页构建函数；落盘后接"立刻刷新"回调；
新开关若约束 OS 动作，必须同步接 06a 的 perms 执行点（失效开关教训）。

**场景 B：调整监控卡显示**
先定档：这个信息属于"可用性"还是"活动状态"？故障覆盖活动的优先级不变；
聊天区只收"不可用"级别，其余进面板。跑 `t_u7_card_layout.py`。

**场景 C：加一个监控出口（如新的环/徽章）**
必须消费 `budget.snapshot` 或 HealthRegistry 的同一个权威数；不得各自
取数（两个出口不一致 = bug）。量不到时画"未知"形态，不画 0。

## 怎么验证你改对了

1. `bash run_tests.sh`（本篇对应 `t_u7_card_layout.py`、`t_l5_bg_drawer.py`、
   `t_d10_user_images.py`）。
2. 抽屉切换顺序测试：依次开监控→知识库→记忆→任务，布局 padding 不留白
   （这正是当年多 drawer 的病灶）。
3. 明暗两套主题下过一遍新面板/设置项。
4. 监控卡与圆环在长对话中数字一致；模型量不到时两者都显示"未知"形态。
