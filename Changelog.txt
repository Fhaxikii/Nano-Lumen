# Changelog

---

## v1.01 (beta)

### What's New
- Lightweight intent routing: small talk keeps tools unloaded; actionable requests enter the tool flow; when the intent is unclear, Nano asks for clarification instead of guessing.

### Improvements
- Dropped hardcoded Chinese-keyword triggers that misfired on unrelated words.
- Unclear intent now gets a natural clarification instead of a forced guess.
- Clarifications keep Nano's own voice rather than sounding mechanical.


### 新增
- 引入轻量意图判断：闲聊不加载工具、需要操作时进入工具流程、意图不明时轻量询问

### 优化
- 去掉依赖中文关键词的硬编码判断，避免无关词误触发工具模式
- 意图不明时不再强行猜测，改为自然澄清
- 澄清时保持 Nano 原有语气，不使用机械式提问

---

## v1.02 (beta)

### What's New
- Tool loading reworked: only loader tools stay resident; everything else loads on demand, with intent detection offering up to 3 candidate tools.

### Improvements
- Removed 5 permanently-resident tools; everything now loads dynamically.
- Candidate tools are suggestions only: when none matches, the model can call the loader itself to pull in more capability.


### 新增
- 工具加载机制重构：常驻仅保留加载工具，其余按需加载；由意图判断给出最多 3 个候选工具

### 优化
- 移除 5 个固定常驻工具，全部改为动态加载
- 候选工具仅作建议，不匹配时模型可自行调用加载工具获取更多能力

## v1.03 (beta)

### What's New
- Tool-use discipline: when unsure about a tool or its parameters, load the tool list first — guessing tool names is forbidden.
- After a failed call, reload the tool definition instead of retrying under a different name.

### Fixes
- Distinguished standalone tools from system-action commands, so window actions are no longer mistaken for sub-actions of a shell command.


### 新增
- 工具使用纪律：不确定工具或参数时先加载工具列表，禁止猜测工具名
- 调用失败后应重新加载工具，不要换名重试

### 修复
- 区分独立工具与操作指令，避免将窗口操作误认为系统命令的子动作

## v1.12 (beta)

### What's New
- Conversation persistence: after a restart, the full context of the same conversation is restored — thinking, tool calls, results, and ordering. Interrupted calls keep an audit trail and are clearly marked on replay.
- Unified long-task handling: commands, external services, and local skills all run in the background — after a timeout control returns to you, you keep working, and Nano wakes you when the task finishes (or at check-ins) with real output and progress.
- Unified tool registry: tool definitions collapsed from 11 scattered places into a single declaration point. Adding a tool now takes one registration; awareness text, scheduling policy, and execution bindings are derived automatically. Conflicts isolate only the conflicting items; startup never blocks on them.
- Runtime kernel and task-state management: scattered runtime states consolidated; each domain has explicit legal state-transition rules.
- Capability health registry: runtime state recorded per capability; failures deduplicated, recovery detected, system events injected into the model.
- Crash breadcrumbs: dangerous operations write a breadcrumb first, so the next launch can locate the cause of death.
- Hard cost cap moved down into the client layer; every API call passes through the gate.
- Knowledge-base vector corruption detection and automatic self-healing.
- Todo cards now have a "reply to this" action: one click answers the right todo instead of the model guessing.

### Improvements
- After waking and continuing, no new `nano ❯` header is started.
- Long-task check-in interval starts at 60 seconds, after which Nano adjusts it from real progress.
- Tool dispatch chain trimmed from 1400+ lines to about 680.
- Monitor card now prioritizes availability over activity state.
- Capability gating became a two-gate design: the manifest layer never hands broken tools to the model, and the execution layer checks again.
- Provider consolidated to a single process-wide instance, lazily loaded.
- Official skill tool declarations now use lowercase types.
- Capability probe framework: externally clock-driven with exponential backoff; failed capabilities can auto-recover.
- The knowledge-base module loads its own environment variables.
- Budget violations raise exceptions instead of sentinel values.
- On-demand tool loading now reports its scope explicitly.
- Async output and background failures converge on a single exit.

### 新增
- **对话持久化**：重启后恢复同一会话的完整上下文，包括思考过程、工具调用、结果和顺序；中断的调用保留审计记录，重放时明确标记
- **长任务统一处理**：命令、外部服务、本地技能都支持后台运行——超时后交还控制权，可继续处理其他事，完成或定期回看时唤醒，能看到真实输出和进度
- **统一工具目录**：工具定义从分散的 11 处收敛为单一声明中心，新增工具只需登记一次，自动派生感知文案、调度策略、执行绑定等；冲突时仅隔离冲突项，不影响整体启动
- 运行时内核与任务状态管理：收拢散落的运行时状态，各领域有明确的合法状态转移规则
- 能力健康登记：按能力登记运行时状态，故障去重、恢复检测、系统事件注入模型
- 崩溃留痕：危险操作前写面包屑，下次启动可定位死因
- 成本硬上限收口到底层客户端，所有 API 调用统一过闸
- 知识库向量库损坏检测与自动自愈
- 待办卡片"回复这条"功能：点一下即可指定回答哪条待办，省去模型猜测

### 优化
- 唤醒后继续说话不再另起一个 `nano ❯` 头
- 长任务回看间隔：首次由系统定为 60 秒，之后由 Nano 根据实际进度自主调整
- 工具执行分派链从 1400 余行精简至约 680 行
- 监控卡改为可用性优先于活动状态
- 能力门控做成双闸：manifest 层不把坏掉能力的工具交给模型，执行层再查一次
- Provider 收成全进程唯一实例，改为懒加载
- 官方技能工具声明改为小写类型
- 能力探针框架：外部时钟驱动，带指数退避，故障能力可自动恢复
- 知识库模块自己加载环境变量
- 超限时抛异常而非哨兵值
- 按需加载工具回执明确作用域范围
- 异步产出与后台故障收口成唯一出口
